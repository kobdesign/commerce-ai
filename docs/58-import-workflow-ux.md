# UX-MER-03 — นำเข้ารายงานทีละขั้น

วันที่: 2026-10-18
สถานะ: ส่งมอบใน local และผ่านการตรวจทางเทคนิค; ยังไม่ได้ UAT กับผู้ค้าจริง

## ผลลัพธ์และขอบเขต

ผู้ค้าเลือกทางเข้ารายงานยอดขายหรือรายการเงินโอนได้ถูก ตรวจคอลัมน์และแก้ข้อผิดพลาดก่อนยืนยัน โดยยังใช้ API การนำเข้า สิทธิ์ และหลักฐานเดิม

- แยก 4 ขั้น: เลือกไฟล์ → เลือกข้อมูลในไฟล์ → ตรวจรายการ → ยืนยันนำเข้า พร้อมแสดงขั้นปัจจุบัน
- หน้าเลือกไฟล์อธิบายข้อมูลที่ต้องเตรียม ขนาดและรูปแบบที่รับ มีตัวอย่างสมมติให้ดาวน์โหลด และลิงก์ไปนำเข้ารายการเงินโอน
- ปุ่มเลือกไฟล์แสดงภาษาไทยและเปิดตัวเลือกไฟล์ของเครื่องตามเดิม
- ตั้งค่าตัวคั่นคอลัมน์อยู่ในส่วนเปิดเพิ่ม ยังคงรองรับจุลภาค อัฒภาค และแท็บ
- บอกช่องจำเป็นที่ยังไม่ได้เลือก แสดงตัวอย่างจากไฟล์ และคงนิยามเงินรับสุทธิต่อรายการ/ค่าธรรมเนียมไม่หักซ้ำ
- หากมีแถวผิด เปิดตัวกรองรายการที่ต้องตรวจก่อน พร้อมแนะนำวิธีแก้ SKU, จำนวน, วันที่, เงิน, รหัสต้นทาง และรายการซ้ำ
- มือถือแสดงรายการเป็นแนวตั้งจาก DOM ตารางชุดเดียว มีชื่อข้อมูลกำกับ ไม่บังคับเลื่อนตารางแนวนอน
- แยกการบันทึกร่างจากการยืนยันยอดขาย แสดงร้าน ไฟล์ และจำนวนก่อนยืนยัน ร่างที่มีข้อผิดพลาดหรือแถวเหมือนกันยังยืนยันไม่ได้
- ย้าย focus ไปข้อผิดพลาดเมื่ออ่านไฟล์ไม่ได้ ไปขั้นที่เปลี่ยน และไปหัวข้อยืนยันหลังบันทึกร่าง
- แสดงหลักฐานต้นฉบับและปุ่มดาวน์โหลดตามเดิม; รายละเอียดรหัสตรวจสอบไฟล์เปิดดูเพิ่มได้
- หน้าสถานะคิวอธิบายว่ากลับมาดูจากร่างที่บันทึกไว้ได้ ปุ่มลองใหม่ยังใช้เฉพาะงานที่ retry ได้และผู้มีสิทธิ์เขียน

## การแก้ความเสี่ยงใน flow เดิม

ก่อนหน้านี้ การย้อนกลับไปเปลี่ยน mapping หลังบันทึกร่างยังเก็บ draft ID เก่าไว้ ทำให้ preview ใหม่กับร่างที่จะยืนยันอาจไม่ตรงกัน

ตอนนี้การกลับไปแก้คอลัมน์จะถอดการเชื่อมกับร่างเดิมและล้าง checkbox ยืนยัน/หลักฐาน/สถานะงานในหน้าปัจจุบัน ผู้ใช้ต้องตรวจและบันทึกร่างสำหรับ mapping ใหม่ก่อนยืนยัน ร่างเก่าในประวัติยังอยู่และไม่ถูกเขียนทับ เมื่อส่งงานเข้าคิวหรือนำเข้าแล้วไม่มีปุ่มแก้ mapping ของงานนั้น

ไม่มีการเปลี่ยนสูตรเงิน ต้นทุน RBAC, tenant/shop scope, server validation, duplicate detection, commit idempotency หรือการจัดเก็บไฟล์ต้นฉบับ

ตัวเลือกบริษัท/ร้านใน header ปิดใช้งานเฉพาะก่อน client hydration แล้วเปิดเมื่อ handler พร้อม ป้องกันการเปลี่ยนค่าเร็วระหว่างโหลดหน้าที่อาจไม่ส่งคำขอสลับร้าน

## ข้อจำกัด

หน้านี้ยังอ่านรายงานยอดขาย CSV ตามรูปแบบที่ระบบรองรับ/การจับคู่คอลัมน์เดิม ไม่ได้เพิ่มการรับไฟล์จริงทุกรูปแบบจาก marketplace หรือการเชื่อม API อัตโนมัติ ลิงก์รายการเงินโอนพาไป workflow `/settlements` เดิม ไม่ได้เปลี่ยนตัวอ่านไฟล์ในรอบนี้

## ตรวจรับ

ผ่าน typecheck, lint, production build (รวม TypeScript) และ `git diff --check`

Browser tests ผ่านครบ 27 กรณีที่เลือก: financial imports 13, foundation 10 และ import entry 4 โดยรอบแรกผ่าน 25/27; แก้การรอร้านใหม่และ label ตัวคั่นไฟล์ จากนั้นพบ race ขณะเริ่มโหลดตัวเลือกร้าน จึงแก้ hydration และทดสอบซ้ำ 8 กรณีที่เกี่ยวข้องผ่านทั้งหมด ไม่ได้อ้างว่า 27 กรณีผ่านใน run เดียว

ตรวจภาพจริงหน้าเลือกไฟล์บน desktop และรายการผิดบนมือถือ 320px แล้ว: `artifacts/import-entry-desktop.png`, `artifacts/import-review-320.png`

ชุดตรวจใหม่ครอบคลุมไฟล์อ่านไม่ได้แล้วแก้ต่อได้, delimiter ที่ไม่ใช่จุลภาค, คอลัมน์จำเป็นที่ยังไม่ได้เลือก, ข้อผิดพลาดบนหน้าจอ 320px, การบันทึกร่างที่ยังมีปัญหา, เปลี่ยน mapping หลัง save แล้วตรวจยอดที่นำเข้าจริง และสิทธิ์อ่านอย่างเดียว

ชุดกระทบยอดเดิมปรับให้รอข้อมูลร้านที่เลือกโหลดเสร็จก่อนเปิดเมนู เพราะการสลับร้านขณะอยู่ `/catalog` ไม่ได้เปลี่ยน URL และการรอ URL อย่างเดียวทำให้ test กดเมนูระหว่าง remount ได้

## UAT ที่ยังต้องทำ

ให้ผู้ค้าที่ไม่เคยใช้ระบบลองเลือกชนิดรายงาน นำไฟล์ที่มีรหัสสินค้าผิดหนึ่งแถวมาแก้ และอธิบายความต่างระหว่าง “บันทึกร่าง” กับ “ยืนยันนำเข้า” โดยไม่บอกตำแหน่งปุ่ม บันทึกเวลาที่ใช้ ความผิดพลาด และจำนวนครั้งที่ต้องช่วยตามแผน UX-MER-05
