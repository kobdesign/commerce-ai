# UX-MER-04 — ผู้ช่วยวิเคราะห์ที่บอกขอบเขตและหลักฐาน

วันที่: 2026-10-18
สถานะ: ส่งมอบใน local และผ่าน browser regression; live-model evaluation และ UAT กับผู้ค้าจริงยังไม่ดำเนินการ

## ผลลัพธ์

หน้า `/ai` เริ่มจากงานที่ผู้ค้าต้องการทำ และบอกชัดว่าผู้ช่วยอ่านอะไรได้ ทำอะไรไม่ได้ และผลมาจากระบบหรือโมเดล AI

- งานตรวจรายการสินค้าใช้เครื่องมือแบบ deterministic ได้แม้ยังไม่เชื่อมโมเดล และติดป้าย “ผลจากระบบ · ไม่ได้เรียก AI”
- งานวิเคราะห์เงินและกระทบยอดพาไป workflow เฉพาะที่มีสูตร หลักฐาน และขั้นยืนยันเดิม แทนการทำให้แชตทั่วไปดูเหมือนตอบข้อมูลการเงินที่ยังอ่านไม่ได้
- ผลตรวจระบุร้าน เวลา ข้อมูลที่ใช้ จำนวน SKU/หมวด ข้อจำกัด และ SKU อ้างอิง; แสดงห้ารายการแรกแล้วเปิดดูที่เหลือได้เพื่อลดความยาวบนมือถือ
- ไม่มี write tool ในผู้ช่วยสินค้า และบอกชัดว่าผลลัพธ์ไม่แก้ข้อมูลหรือสร้างงานอัตโนมัติ
- เมื่อยังไม่ตั้งค่าโมเดล จะไม่แสดงช่องถามหรือปุ่ม AI ที่ใช้งานไม่ได้ แต่ยังเปิดงานตรวจข้อมูลและผู้ช่วยกระทบยอดได้
- ประวัติแสดงเฉพาะร้านที่เลือกและสิบครั้งล่าสุด แก้ช่องว่างเดิมที่ประวัติระดับบริษัทอาจรวมผลของหลายร้าน
- สภาพแวดล้อม local/staging ระบุว่าเป็นข้อมูลตัวอย่าง ส่วน production จะไม่ถูกติดป้ายว่า synthetic โดยไม่มีหลักฐานจาก environment

## ขอบเขต AI และ business logic

ผู้ช่วยทั่วไปอ่านเฉพาะ catalog ผ่าน typed `readCatalog` tool ที่ตรวจ tenant, shop grant และ RLS เดิม ไม่อ่านยอดขาย ต้นทุน กำไร ลูกค้า หรือไฟล์ดิบ และไม่มีเครื่องมือเขียนข้อมูล ส่วนการเงินยังใช้ financial review assistant ที่มี evidence contract, draft และ human confirmation ตาม FIN-AI-02–04

เส้นทาง live ใช้ AI SDK 7 ที่ติดตั้งอยู่ (`ToolLoopAgent`, schema ของ tool, step limit, timeout และ usage metadata) ผ่าน server เท่านั้น คีย์ไม่ถูกส่งไป browser. Prompt กำหนดให้ข้อมูลจากผู้ใช้และสินค้าเป็น untrusted input, ห้ามขยายสิทธิ์หรือแต่งยอด และให้กล่าวว่าเป็นข้อมูลตัวอย่างเมื่อ evidence ระบุ `isSynthetic=true` เท่านั้น รอบตรวจนี้ไม่ได้เปิดโมเดลหรือส่งข้อมูลออกภายนอก

## การตรวจรับ

- browser flow บน 320px: เลือกงาน ตรวจสินค้า เห็นเวลา/ขอบเขต/ข้อจำกัด/SKU และไม่มี horizontal overflow
- ผลและประวัติของ TikTok ไม่ปรากฏเมื่อสลับเป็น Shopee
- history API บังคับ `shopId`, ปฏิเสธร้านต่าง tenant และไม่คืน run ข้ามร้าน
- regression เดิมของ login → เพิ่มสินค้าหลายหมวด → เปิดผู้ช่วย → ตรวจ evidence ยังทำงาน
- unit/integration ตรวจว่า run deterministic ใช้ provider token และค่าใช้จ่ายเป็นศูนย์ ไม่เผย SKU ต่าง tenant และอ่านประวัติได้เฉพาะร้านที่ได้รับอนุญาต
