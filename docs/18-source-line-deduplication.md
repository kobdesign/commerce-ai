# Source line identity และการป้องกันยอดขายซ้ำ — v0.6

วันที่ตรวจรับ: 16 กันยายน 2026

## ปัญหาธุรกิจ

ก่อน v0.6 ระบบป้องกันการยืนยันร่างเดิมซ้ำได้ แต่ถ้ารายการขายเดียวกันอยู่ในไฟล์คนละไฟล์และเนื้อหาไฟล์เปลี่ยน ระบบอาจนับยอดซ้ำ การเริ่มทำ refund และ settlement บนข้อมูลแบบนี้จะทำให้จับคู่เหตุการณ์ผิดรายการได้

## พฤติกรรมที่เพิ่ม

- เพิ่มช่อง mapping **รหัสรายการต้นทาง** แบบ optional สำหรับ ID ระดับ order line จาก marketplace
- แนะนำหัวคอลัมน์ `source_line_id`, `line_id`, `order_item_id` และ `item_id` โดยอัตโนมัติ
- แสดงรหัสต้นทางใน preview เพื่อให้ผู้ใช้เทียบกับไฟล์ได้
- หากไม่มีรหัสต้นทาง ระบบอธิบายขอบเขตว่าป้องกันได้เฉพาะการยืนยันร่างเดิมซ้ำ
- หาก ID ซ้ำภายในไฟล์หรือซ้ำกับรายการที่ยืนยันในร้านแล้ว แถวนั้นเป็นข้อมูลที่ต้องแก้ไขและยืนยันนำเข้าไม่ได้
- ไฟล์ตัวอย่างมี `source_line_id` เพื่อสาธิต flow ที่ปลอดภัยกว่า

รายการซ้ำถูกหยุดใน import preview ก่อนสร้างยอดขาย จึงไม่ส่งเข้า Review Inbox ซึ่งใช้สำหรับข้อมูลที่ยืนยันแล้วแต่ยังขาดต้นทุน

## กติกาข้อมูล

- ID ยาว 1–150 ตัวอักษร ตัดช่องว่างหัวและท้ายก่อนตรวจ
- ID ต้องไม่ซ้ำภายใน tenant และร้านเดียวกัน
- ร้านต่างกันใช้ ID เดียวกันได้ เพราะแต่ละ marketplace อาจมี namespace ของตัวเอง
- ไฟล์เดิมที่ไม่มี ID ยังนำเข้าได้ เพื่อรองรับรายงานเก่า แต่ไม่มีการรับประกัน deduplication ข้ามไฟล์
- `sales_lines` ยังคง append-only สำหรับ runtime role

Migration `0007-sales-line-source-identity.sql` เพิ่ม `source_line_id` และ partial unique index `(tenant_id, shop_id, source_line_id)` เฉพาะแถวที่มี ID การตรวจใน preview ช่วยผู้ใช้แก้ไฟล์ก่อน ส่วน unique index เป็นชั้นสุดท้ายสำหรับการยืนยันสองไฟล์พร้อมกัน

## ผลตรวจ

- TypeScript, ESLint และ production build ผ่าน
- Integration tests **47/47** ผ่าน รวมการตรวจไฟล์ถัดมาและ concurrent commit สองไฟล์ที่ใช้ ID เดียวกัน
- Browser tests **15/15** ผ่าน รวม flow มือถือที่นำเข้าไฟล์แรกและบล็อก ID เดิมในไฟล์ถัดมา
- ไฟล์ที่ไม่มี source line ID ในชุด regression เดิมยังทำงานได้

## ขอบเขตถัดไป

ยังต้องยืนยันชื่อคอลัมน์และความคงที่ของ ID จากรายงาน TikTok, Shopee และ Lazada จริงที่ลบข้อมูลส่วนบุคคลไม่จำเป็นออกแล้ว ขั้นถัดไปคือใช้ identity นี้เชื่อม financial events เช่น refund และ settlement โดยไม่แก้ไข sales fact เดิม
