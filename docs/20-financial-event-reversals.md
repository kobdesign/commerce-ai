# การแก้กลับรายการการเงินแบบ append-only — v0.8

วันที่ตรวจรับ: 16 กันยายน 2026

## ปัญหาธุรกิจ

รายการ refund หรือเครดิตค่าธรรมเนียมที่บันทึกผิดไม่ควรถูกแก้ไขหรือลบ เพราะจะทำให้หลักฐานและตัวเลขย้อนหลังเปลี่ยนโดยไม่เห็นผู้ดำเนินการ รุ่นนี้จึงเพิ่มการแก้กลับด้วยรายการใหม่ที่มีผลตรงข้ามกับต้นฉบับ

## Flow ที่ใช้งานได้

เจ้าของหรือฝ่ายการเงินเลือก **แก้กลับรายการ** จากประวัติรายการปรับยอด ระบบแสดงประเภท คำสั่งซื้อ จำนวนเงิน และรหัสต้นทางเดิมก่อนให้กรอก:

- วันที่และเหตุผลที่แก้กลับ
- การยืนยันว่าต้องการยกเลิกผลโดยเก็บรายการเดิมไว้

ระบบสร้างรหัสรายการแก้กลับที่คงที่และไม่ซ้ำต่อร้านจากรายการเดิมให้เอง ผู้ใช้จึงไม่ต้องคิดหรือกรอกรหัสทางเทคนิค หน้าโทรศัพท์แสดงประวัติเป็นการ์ดและวางปุ่ม **แก้กลับรายการ** ไว้ใต้หลักฐานโดยไม่ต้องเลื่อนตารางแนวนอน

ระบบคัดลอกคำสั่งซื้อ ประเภท สกุลเงิน และจำนวนจากต้นฉบับ ผู้ใช้จึงไม่สามารถกำหนดยอดแก้กลับให้ต่างจากหลักฐานเดิม รายการต้นฉบับเปลี่ยนสถานะเป็น **ถูกแก้กลับแล้ว** และรายการใหม่แสดงเป็น **รายการแก้กลับ**

## กติกาและความถูกต้อง

- ต้นฉบับหนึ่งรายการแก้กลับได้หนึ่งครั้ง
- ไม่อนุญาตให้แก้กลับรายการแก้กลับอีกชั้น
- refund เดิมมีผลลบและรายการแก้กลับมีผลบวก
- fee rebate เดิมมีผลบวกและรายการแก้กลับมีผลลบ
- replay ด้วยรหัสและข้อมูลเดิมไม่เพิ่มยอดซ้ำ แต่รหัสเดิมที่มีข้อมูลต่างกันถูกปฏิเสธ
- advisory lock ป้องกันคำขอพร้อมกันสร้างการแก้กลับมากกว่าหนึ่งรายการ
- migration `0010-financial-event-reversals.sql` เพิ่ม composite foreign key และ unique partial index
- migration `0011-financial-reversal-integrity.sql` เพิ่ม trigger บังคับให้ order, event type, amount และ currency ตรงกับต้นฉบับ แม้มีการเรียกฐานข้อมูลโดยไม่ผ่าน UI
- การแก้กลับสร้าง audit event `financial_event.reversed` และ runtime role ยังไม่มีสิทธิ์ UPDATE/DELETE

ตัวอย่าง synthetic: เงินรับเดิม 319 บาท ต้นทุน 250 บาท เมื่อ refund 100 บาท เงินรับหลังปรับเป็น 219 บาทและส่วนต่าง -31 บาท เมื่อแก้กลับ refund เงินรับกลับเป็น 319 บาทและส่วนต่าง 69 บาท โดย sales fact เดิมไม่ถูกแก้ไข

## ผลตรวจ

- TypeScript, ESLint, production build และ migration ผ่าน
- Integration tests **53/53** ผ่าน รวม replay, competing reversals, reversal-of-reversal, role/tenant isolation, append-only grants และ forged amount ที่ฐานข้อมูลปฏิเสธ
- Browser tests **16/16** ผ่าน รวม flow มือถือจากนำเข้ารายการขาย → refund → แก้กลับ → ตรวจเงินรับและส่วนต่างที่คืนค่าเดิม
- ตรวจฟอร์มที่ viewport 390 × 844 แล้ว ช่องรหัสได้รับ focus อัตโนมัติ ปุ่มหลักมีขนาดเหมาะกับการแตะ และไม่พบ page-level horizontal overflow หรือ browser error

## ขอบเขตที่ยังไม่รับรอง

- ยังเป็น manual correction และ THB-only ไม่ใช่ marketplace statement adapter หรือ bank reconciliation
- ประวัติหน้าเว็บแสดง 100 รายการล่าสุดและยังไม่มี pagination สำหรับเลือกรายการเก่ากว่านั้น
- ยังไม่มี partial correction เพราะการแก้กลับต้องหักล้างต้นฉบับเต็มจำนวน หากต้องการยอดใหม่ต้องสร้างเหตุการณ์ใหม่แยกต่างหาก
- settlement, payout, cancellation, return-to-stock, affiliate, ads, FX และ VAT semantics ยังต้องออกแบบจากรายงานจริง
