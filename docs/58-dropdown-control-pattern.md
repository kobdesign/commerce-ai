# Dropdown control pattern — v1.0

## วัตถุประสงค์

ผู้ใช้ควรเรียนรู้วิธีเลือกข้อมูลเพียงครั้งเดียวแล้วใช้ซ้ำได้ทุกหน้า โดยคงความเหมาะสมของแต่ละบริบทไว้ ระบบใช้ความสูง เส้นขอบ รัศมี ลูกศร สถานะ hover, focus และ disabled จาก control tokens ชุดเดียวกัน

## รูปแบบที่อนุญาต

1. **Select** ใช้เมื่อเลือกได้จากรายการที่ระบบกำหนดเท่านั้น เช่น ประเภทเหตุการณ์ สถานะ หรือคอลัมน์นำเข้า ใช้ native select เพื่อรักษาพฤติกรรมคีย์บอร์ดและอุปกรณ์เคลื่อนที่ แล้วรับภาพจาก global control tokens
2. **Combobox** ใช้เมื่อค้นหาหรือเพิ่มค่าใหม่ได้ เช่น หมวดสินค้า รายการต้องกรองตามข้อความที่พิมพ์และบอกชัดว่าค่าใหม่ใช้ได้
3. **Compact select** ใช้เฉพาะตัวกรอง ตาราง และตัวสลับบริษัท/ร้าน โดยลดพื้นที่แต่ยังใช้ลูกศร สถานะ focus และคำเรียกแบบเดียวกัน

ห้ามสร้าง dropdown เฉพาะหน้าโดยกำหนดเส้นขอบ ลูกศร หรือเมนูใหม่เอง หากต้องเพิ่มพฤติกรรมให้ขยาย component กลางหรือ control tokens ก่อน

## การใช้ในหน้าสินค้า

- “หมวดสินค้า” เป็น combobox เพราะผู้ใช้เลือกหมวดเดิมหรือพิมพ์หมวดใหม่ได้
- “หน่วยขาย” ใช้ fixed-choice combobox จาก component เดียวกัน จึงมีขนาด ลูกศร เมนู และการใช้คีย์บอร์ดตรงกัน
- หน้าสร้างและหน้าแก้ไขใช้ component และข้อความชุดเดียวกัน

## เกณฑ์ตรวจรับ

- ทุก control มีชื่อที่ screen reader อ่านได้ และใช้งานด้วย Tab, ลูกศร, Enter, Home, End และ Escape ได้ตามชนิด
- form control ปกติสูง 42px และไม่ทำให้หน้ากว้างเกิน viewport ที่ 390px
- ค่า disabled แยกจากค่าใช้งานได้ชัดเจน เมนูไม่เปิดเมื่อ disabled
- การเปลี่ยนค่าผ่าน custom component ต้องตั้งสถานะข้อมูลยังไม่บันทึกเหมือน input ปกติ
- native select ที่เหลือทั้งหมดรับภาพจาก global tokens; workspace picker และ table filter ใช้ compact variant เท่านั้น
