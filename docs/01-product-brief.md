# Product brief v0.2

## สิ่งที่ยืนยันจากผู้ใช้

- ธุรกิจขายกางเกงชิโนหลายความยาว หลายสี/ไซซ์ ผ่าน TikTok, Shopee และ Lazada
- มีความกังวลเรื่องค่าธรรมเนียม ค่าแอด ค่าส่ง และค่าใช้จ่ายบริษัท บางรายการขาดทุนตามที่ผู้ใช้เล่า ยังไม่ได้ตรวจด้วยข้อมูลจริง
- ผู้ใช้ต้องการพัฒนาแอปช่วยร้านแฟน และอาจให้ร้านอื่นใช้งานเป็นแพลตฟอร์ม
- ผู้ใช้ย้ำให้รองรับสินค้าประเภทอื่นในอนาคต กางเกงเป็นกรณีทดลองแรก ไม่ใช่ขอบเขต product model
- ต้องมี AI Native ตั้งแต่ Day One, Multi-Tenant และแผนรองรับ Enterprise
- ผู้ใช้อนุญาตให้เริ่มทำแผนเวอร์ชันแรกและ backlog ตาม SDLC ที่เสนอ

## สมมติฐานที่ยังต้องยืนยัน

- เวอร์ชันแรกเป็น web application สำหรับเจ้าของร้านและผู้ดูแลการเงิน
- เริ่มด้วยไฟล์จาก TikTok เพราะเป็นจุดปัญหาที่เล่าชัดที่สุด
- หนึ่งองค์กรมีหลายบริษัทและหลายร้านได้ แต่ pilot ใช้โครงสร้างเท่าที่จำเป็น
- ข้อมูลต้นทุนสินค้าและค่าแอดมีแหล่งอ้างอิงที่นำเข้าได้ หากไม่มีต้องแสดงความไม่ครบถ้วน
- ทีมพัฒนาขนาดเล็ก; ยังไม่ทราบ stack งบ โฮสติ้ง และจำนวนออเดอร์

## ผู้ใช้และงานที่ต้องทำ

| ผู้ใช้ | งานหลัก | ผลลัพธ์ |
|---|---|---|
| เจ้าของ | ตรวจเงินเหลือและรายการที่ต้องจัดการ | เห็นที่มาของตัวเลขและข้อจำกัด |
| การเงิน | ตรวจไฟล์ จับคู่รายการเงิน ใส่ต้นทุน | ตรวจย้อนกลับและแก้ข้อมูลได้มีประวัติ |
| การตลาด | ดูยอดขาย/ค่าแอดในขอบเขตที่ได้รับ | ใช้ข้อมูลเดียวกับทีมโดยไม่เห็นต้นทุนที่ไม่มีสิทธิ์ |
| ผู้ตรวจสอบ | อ่านหลักฐานและประวัติ | ตรวจสอบได้โดยไม่แก้รายการ |

## MVP: งานที่ทำให้จบ

1. สร้างองค์กร เชิญสมาชิก จำกัดสิทธิ์ตามองค์กรและร้าน
2. นำเข้าไฟล์ต้นทาง เก็บ provenance และตรวจรายการซ้ำ
3. AI เสนอ mapping คอลัมน์/สินค้า ผู้ใช้ยืนยันก่อนนำเข้าเป็นข้อมูลธุรกิจ
4. ระบุรายการเงินที่จับคู่ได้ จับคู่ไม่ได้ หรือมีข้อแตกต่าง
5. คำนวณเงินเหลือก่อนและหลังค่าแอด พร้อม actual/allocated/estimated/incomplete
6. AI ตอบคำถามจาก typed tools และหลักฐานที่ผู้ใช้มีสิทธิ์
7. สรุปรายการต้องตรวจ สร้างงานภายใน และติดตามสถานะ
8. มี audit, usage, backup/restore และการวัดคุณภาพ AI
9. Catalog กลางรองรับ physical products หลายหมวดและสินค้าที่ไม่มีตัวเลือก โดยไม่บังคับสี/ไซซ์; ตรวจด้วยตัวอย่างเสื้อผ้าและสินค้าหมวดอื่น

## ขอบเขตที่ยังไม่เปิดใน MVP

- ส่งคำสั่งปรับราคา งบแอด คืนเงิน หรือสั่งซื้อสินค้าไปยังแพลตฟอร์ม
- ระบบบัญชีตามกฎหมาย ภาษี หรือการยื่นแบบครบวงจร
- Stock sync, ERP เต็มระบบ, การพยากรณ์สินค้า และระบบช่วยเลือกไซซ์
- การบริหารล็อต/วันหมดอายุ/serial, การแปลงหน่วยชั่งตวง, แตกชุดสินค้าเป็นส่วนประกอบ, digital entitlement และ subscription lifecycle
- เชื่อม marketplace API ครบทุกช่องทางก่อนพิสูจน์ workflow
- Enterprise deployment แยกทรัพยากรเต็มรูปแบบ หรือการอ้างว่าผ่านมาตรฐานรับรอง

ออกแบบขอบเขตข้อมูลและ extension points รองรับ แต่ต้องมี acceptance criteria ใหม่ก่อนเพิ่มแต่ละความสามารถ

## ตัวชี้วัด pilot

- เวลาทำรายงานและตรวจรายการ: วัด baseline จากงานจริง แล้วตั้งเป้าลดเวลาร่วมกัน
- ความถูกต้อง: golden cases ต้องตรงทุกกรณีตามวิธีปัดเศษที่กำหนด
- ความครบถ้วน: แสดงจำนวนรายการที่ขาดต้นทุน ขาดหลักฐาน หรือยังจับคู่ไม่ได้
- ประโยชน์ AI: งานที่ผู้ใช้ทำสำเร็จพร้อมหลักฐาน และอัตราที่ต้องแก้คำตอบ
- ต้นทุน: AI/infra/support ต่อองค์กรและต่อ workflow
- การใช้งานซ้ำ: ผู้ใช้กลับมาตรวจรายงานในรอบงานถัดไปโดยไม่ต้องให้นักพัฒนาทำแทนทั้งหมด

ยังไม่มี baseline หรือเป้าหมายเชิงพาณิชย์ที่ยืนยันแล้ว ห้ามนำค่าที่สมมติไปแสดงเป็นผลสำเร็จ
