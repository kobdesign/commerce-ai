# Usability review — Review Inbox

วันที่ทดสอบ: 16 กันยายน 2026

## งานที่จำลอง

ทดสอบด้วย owner และข้อมูล synthetic ตั้งแต่นำเข้า CSV ที่ใช้ SKU ไม่มีต้นทุน → ตรวจ mapping → บันทึกร่าง → ยืนยันนำเข้า → เปิดรายการที่ต้องตรวจ → กรอกต้นทุน/เหตุผล → แก้ validation error → ยืนยันสำเร็จ → ตรวจ success feedback

Viewport ที่ใช้:

- มือถือ 390 × 844 px
- เดสก์ท็อป 1280 × 900 px

## ปัญหาที่พบและแก้แล้ว

### Action หลักอยู่นอกจอ

ก่อนแก้ บนมือถือพื้นที่ตารางกว้าง 1,101 px แต่ viewport ของตารางกว้าง 354 px ช่องต้นทุน เหตุผล และปุ่มยืนยันจึงอยู่นอกจอทั้งหมด

ที่เดสก์ท็อป 1280 px พื้นที่ตารางกว้าง 992 px แต่ตารางกว้าง 1,159 px ปุ่มยืนยันเริ่มที่พิกัดซ้าย 1,312 px และมองไม่เห็นจนกว่าจะเลื่อนแนวนอน

แก้โดย:

- ใช้การ์ดหนึ่งคอลัมน์บนมือถือ
- ใช้การ์ดสองคอลัมน์สำหรับ viewport 681–1499 px
- ใช้ตารางเมื่อ viewport ตั้งแต่ 1500 px ซึ่งมีพื้นที่พอ
- แสดง label ต้นทุนและเหตุผลภายในแต่ละการ์ด
- ทำปุ่มยืนยันเต็มความกว้างของการ์ด

ผลหลังแก้ที่มือถือ:

- ช่องต้นทุนและเหตุผลกว้าง 322 px สูง 44 px
- ปุ่มยืนยันกว้าง 322 px สูง 46 px
- controls ทั้งหมดอยู่ภายใน viewport และไม่มี page-level horizontal overflow

ผลหลังแก้ที่เดสก์ท็อป 1280 px:

- grid สองคอลัมน์ คอลัมน์ละ 470 px
- ปุ่มยืนยันกว้าง 428 px และอยู่ใน viewport
- ไม่มี page-level horizontal overflow

### เหตุผลที่จำเป็นไม่ชัดเจน

เพิ่มคำว่า **จำเป็น** และคำแนะนำ **อย่างน้อย 3 ตัวอักษร** ใต้ช่องเหตุผล พร้อมคง accessible name ที่อ้างอิง order ID

## สิ่งที่ผ่านโดยไม่ต้องแก้

- navigation ไป Review Inbox หาได้จากเมนูหลัก
- ข้อมูล order, SKU, วันที่ขาย, จำนวน และเงินรับสุทธิอยู่ก่อนช่องตัดสินใจ
- ลิงก์เปิดร่างนำเข้าอยู่ในรายการเดียวกับข้อมูลที่จะยืนยัน
- ปุ่มถูก disabled จนกรอกต้นทุนและเหตุผลขั้นต่ำครบ
- เมื่อกรอกต้นทุน `abc` ข้อความ error ปรากฏใน viewport และผู้ใช้แก้ข้อมูลต่อได้
- หลังยืนยัน 200 บาท success message ปรากฏใน viewport รายการหายจาก inbox และ empty state แสดงทันที
- ไม่พบ console error หรือ Next.js error overlay
- targeted browser regression ของ missing-cost flow ผ่าน

## การปรับปรุงรอบที่สอง

- เปลี่ยนประวัติร่างเป็น disclosure: เปิดอยู่เมื่อเข้าหน้านำเข้า แต่พับอัตโนมัติหลังเลือกไฟล์ เพื่อลดความยาวและรักษาสมาธิที่งานจับคู่คอลัมน์
- ผู้ใช้เปิด “แสดงประวัติ” ระหว่างทำงานและเปิดร่างย้อนหลังได้เสมอ
- เพิ่ม touch target ของ navigation แนวนอน ปุ่มออกจากระบบ ตัวเลือกบริษัท และตัวเลือกร้านค้าบนมือถือเป็นอย่างน้อย 44 px
- ตรวจที่ 390 × 844 px แล้ว navigation ทุกเมนูสูง 44 px, ปุ่มออกจากระบบ 44 × 44 px และ select ทั้งสองรายการสูง 44 px
- ไม่พบ page-level horizontal overflow ก่อนหรือหลังเลือกไฟล์

Automated browser tests ตรวจทั้งการพับหลังเลือกไฟล์ การเปิด disclosure และการเปิดร่างย้อนหลัง ส่วน visual check ใช้ข้อมูล synthetic เท่านั้น

## ข้อสังเกตรอบถัดไป

- ก่อน production ควรทำ moderated test กับผู้ดูแลร้าน 3–5 คน โดยใช้ไฟล์รายงานจริงที่ลบข้อมูลส่วนบุคคล เพื่อวัดเวลาทำงาน อัตราผิดพลาด และความเข้าใจคำว่า “ต้นทุนย้อนหลัง”
