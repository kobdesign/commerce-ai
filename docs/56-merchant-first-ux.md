# UX-MER-01 — หน้าเริ่มต้นสำหรับผู้ค้าชาวไทย

วันที่: 2026-10-18
สถานะ: implemented locally; technical checks passed; merchant usability acceptance pending

## เป้าหมายและขอบเขต

ผู้ค้าหรือทีมร้านที่ไม่เคยใช้ระบบควรเลือกงานแรกได้จากภาษาที่คุ้นเคย และตามข้อมูลกลับถึงหลักฐานได้ โดยคง business logic, tenant/shop scope, สิทธิ์, การตรวจยืนยัน และความสามารถเดิมทั้งหมด

รอบนี้ปรับหน้าแรกและ navigation เป็นฐานสำหรับปรับแต่ละ workflow ต่อไป ไม่ได้อ้างว่าทุกแบบฟอร์มง่ายแล้ว หรือผ่าน UAT กับร้านจริง ไม่เปลี่ยน API/database และไม่เพิ่มการเรียก AI อัตโนมัติ

## สิ่งที่ส่งมอบ

- หน้าแรกแสดงงานที่ทำได้ตามสิทธิ์: ดูสินค้า/สต็อก, คำสั่งซื้อ, นำรายงานยอดขายเข้า, ดูเงินรับและต้นทุน
- คู่มือ 1–3 ขั้นพร้อมสิ่งที่ต้องเตรียมและทางไปทำงาน; ผู้ใช้ข้ามขั้นได้ เปิดอัตโนมัติเมื่อไม่มีสินค้าที่แสดง ไม่สร้างเปอร์เซ็นต์ onboarding หรือสถานะเสร็จปลอม
- ไม่มีร้าน: แนะนำเพิ่มร้านสำหรับ owner และแนะนำให้ขอสิทธิ์สำหรับบทบาทอื่น
- สินค้าขาดต้นทุนแสดงเฉพาะผู้มีสิทธิ์อ่านต้นทุน; จำนวนจาก catalog จำกัด 200 รหัสและระบุเมื่อถึงขีดจำกัด
- อธิบาย SKU ด้วยตัวอย่างสินค้า, เงินรับเทียบกำไร, กระทบยอดเงินโอน และขอบเขตผู้ช่วย
- จัดการร้าน/บริษัทในส่วนเปิดดูเพิ่มเติม; เลือกบริษัทและร้านยังอยู่ด้านบนทุกหน้า
- เมนูประจำหกรายการสำหรับ owner; รายการการเงินอื่นและเครื่องมือเพิ่มเติมใช้ disclosure ที่เข้าถึงด้วยคีย์บอร์ด
- มือถือแสดงภาพรวม/สินค้า/คำสั่งซื้อ และปุ่มเมนูทั้งหมด; ย่อเมนูหลังเปลี่ยนหน้าเพื่อให้เห็นงานทันที แสดงชื่อหน้าปัจจุบันที่ปุ่ม และเมื่อเปิดเมนูจะแสดงกลุ่มของหน้าปัจจุบันให้เอง
- เลือก active route ที่เฉพาะเจาะจงที่สุด ป้องกันทีมและสิทธิ์ติด active พร้อม Service Access
- ศัพท์เทคนิคใน navigation เปลี่ยนเป็นคำไทย แต่ URL และหน้าทำงานเดิมคงอยู่

## แผนที่ความสามารถเดิม

| ตำแหน่ง | เส้นทาง |
| --- | --- |
| งานประจำ | `/`, `/catalog`, `/orders`, `/imports`, `/performance`, `/ai` |
| สต็อกกลาง | `/inventory` รวม SKU จากทุกช่องทางที่ผู้ใช้มีสิทธิ์ พร้อมช่องทางขาย และเปิด ledger รายสินค้าต่อได้ |
| เงินและรายการที่ต้องตรวจ | `/settlements`, `/financial-events`, `/expenses`, `/reviews` |
| ตั้งค่าและเครื่องมือเพิ่มเติม | `/team`, `/activity`, `/integrations/inbox`, `/team/service-access`, `/support/poc` |
| สินค้าแต่ละรายการ | แก้ไข, ตัวเลือก, lifecycle, inventory, reservations และ listing mapping ผ่านหน้าสินค้าเดิม |
| จัดการร้านและบริษัท | disclosure หน้าแรก; การสลับร้าน/บริษัทยังใช้ header เดิม |

ทุกกลุ่มกรองสิทธิ์เดิมก่อน render; ย้ายเมนูไม่ใช่การเปลี่ยน authorization ฝั่ง server. Support track ยัง paused และหน้าทดลองยังไม่ใช่ live support.

## ขั้นต่อไปของการปรับ UX

| ลำดับ | งาน | เกณฑ์ตรวจรับ |
| --- | --- | --- |
| UX-MER-02 — ส่งมอบ local; รอ UAT ([ผลตรวจ](57-product-entry-ux.md)) | เพิ่มสินค้า: ข้อมูลจำเป็นก่อน รายละเอียดเสริมทีหลัง; คำไทยและตัวอย่างสำหรับรหัส/สี/ขนาด; คงหลายหมวดและหลายตัวเลือก | มือใหม่เพิ่มสินค้าหนึ่งตัวเลือกและหลายตัวเลือกได้; ไม่ทำราคาหรือสต็อกเดิมสูญหาย |
| UX-MER-03 — ส่งมอบ local; รอ UAT ([ผลตรวจ](58-import-workflow-ux.md)) | นำเข้า: เลือกชนิดงาน → เลือกไฟล์ → ตรวจปัญหา → ยืนยัน; ข้อผิดพลาดชี้แถวและวิธีแก้ | ไม่ยืนยันโดยเผลอ; duplicate/idempotency/preview/evidence ไม่เปลี่ยน; ไม่อ้างรองรับไฟล์ marketplace จริงก่อนตรวจรับ |
| UX-MER-04 — ส่งมอบ local; รอ UAT ([หน้าเงิน](59-merchant-finance-ux.md), [ผู้ช่วย](60-merchant-assistant-ux.md)) | เงินและ AI: ภาษาธุรกิจ, ที่มาตัวเลขเปิดดูต่อ, อธิบายผลกระทบก่อนแก้กลับ/ยืนยัน | ผู้ใช้แยกเงินรับ/ส่วนต่าง/เงินโอนได้; ยังไม่เรียกกำไรสุทธิเมื่อค่าใช้จ่ายไม่ครบ; ผู้ช่วยระบุขอบเขตและหลักฐาน; AI ร่างให้คนยืนยัน |
| UX-MER-04b — ส่งมอบ local; รอ UAT ([ผลตรวจ](61-central-inventory-ux.md)) | สต็อกกลาง: รวม SKU พร้อมคงเหลือ/จอง/พร้อมขาย ค้นหาและเปิด ledger ต่อ | ผู้ใช้หาสต็อกกลางจากเมนูหลักและอธิบายสามยอดได้; ไม่อ้างว่าเป็นยอด marketplace realtime |
| UX-MER-05 | ทดสอบกับผู้ค้าจริงและปรับตามปัญหา | บันทึกความสำเร็จ เวลา ความผิดพลาด และจำนวนครั้งที่ขอความช่วยเหลือจากการใช้ครั้งแรก |

ข้อค้นพบสำหรับ UX-MER-04: ตารางเทียบคำสั่งซื้อในหน้ากระทบยอดมีขีดจำกัด 100 แถวและเรียงยอดต่างก่อน รายการที่ตรงกันใหม่อาจไม่อยู่ในหน้าที่แสดงเมื่อสะสมข้อมูลมาก ควรเพิ่มการค้นหา/กรอง/แบ่งหน้าและคำอธิบายขอบเขต โดยรักษาสูตรและหลักฐานเดิม รอบนี้ยังไม่เปลี่ยนตารางนั้น; browser test ของการกระทบยอดแยกร้านทดสอบเพื่อไม่ให้ประวัติ demo ทำให้ผลไม่แน่นอน

แนวทางคือเปิดรายละเอียดเมื่อจำเป็น ไม่สร้างสองระบบ simple/advanced ที่มี business rules แยกกัน และไม่ใช้แชตเป็นทางเข้าเพียงทางเดียว เป้าหมายเป็นสมมติฐานที่ต้องวัดกับร้านจริง ไม่ใช้ความสามารถด้านเทคนิคแทนผล usability

## แผน UAT ร้านจริง (ยังไม่ได้ดำเนินการ)

เริ่มกับผู้ค้าชาวไทยประมาณ 5 คนที่ยังไม่เคยใช้ระบบ เป็นการค้นปัญหา ไม่ใช่ผลเชิงสถิติ ให้ลองโดยไม่สอนเส้นทางล่วงหน้า:

1. หาร้านที่กำลังทำงานอยู่และเปลี่ยนร้านให้ถูก
2. เพิ่มสินค้าที่มี S/M/L พร้อมราคาและต้นทุน
3. นำเข้ารายงานตัวอย่างและแก้รายการที่ไม่ตรงก่อนยืนยัน
4. อธิบายว่าตัวเลขเงินรับและต้นทุนหมายถึงอะไร และเปิดหลักฐานของยอดหนึ่งรายการ
5. หาเครื่องมือเงินโอน กลับหน้าแรก และเปิดผู้ช่วย

เป้าหมาย pilot ที่เสนอ: อย่างน้อย 4 จาก 5 คนทำงานหลักสำเร็จโดยไม่บอกตำแหน่งปุ่ม และไม่มีการยืนยันผิดร้าน/ผิดยอด ระบุเวลาและจุดขัดข้องตามผลจริงก่อนตั้งเป้าลดเวลา ห้ามรายงานว่าผ่านก่อนทดสอบ
