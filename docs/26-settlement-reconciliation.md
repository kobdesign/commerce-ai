# กระทบยอดเงินโอนตาม statement — v1.3

วันที่ตรวจ: 17 กันยายน 2026

## ปัญหาที่แก้

เงินรับสุทธิในรายงานยอดขายบอกยอดระดับคำสั่งซื้อ แต่ยังไม่ยืนยันว่าแพลตฟอร์มรวมยอดเหล่านั้นเข้า payout ตาม statement ครบหรือไม่ รุ่นนี้เพิ่มบัญชีกลางสำหรับบันทึก allocation ของแต่ละบรรทัดใน statement แล้วเทียบทั้งระดับรอบโอนและระดับคำสั่งซื้อ

## Flow ที่ใช้งานได้

1. Owner หรือ Finance ระบุรหัสรอบโอน วันที่ และยอดรวมตาม statement
2. บันทึกหนึ่งบรรทัดต่อการจัดสรรเงินให้คำสั่งซื้อ พร้อมรหัสบรรทัดต้นทางและหลักฐาน
3. ระบบรวมหลายบรรทัดเป็นรอบโอน และแสดงส่วนต่างระหว่างยอดจัดสรรกับยอดรวมใน statement
4. ระบบจับคู่เลขคำสั่งซื้อกับยอดขายที่นำเข้า และเทียบยอดที่ควรได้รับหลังรวม refund หรือ fee rebate ที่บันทึกไว้
5. รอบโอนจะเป็น **กระทบครบ** เมื่อยอดจัดสรรเท่ากับยอดตาม statement และทุกบรรทัดพบคำสั่งซื้อ
6. รายการผิดใช้ **แก้กลับบรรทัด** ระบบสร้างรายการหักล้างและเก็บต้นฉบับไว้

โครงสร้างรองรับทั้งหนึ่ง payout ที่รวมหลายออเดอร์ และหนึ่งออเดอร์ที่ได้รับเงินหลาย payout โดยไม่ผูกกับหมวดสินค้า จึงใช้กับเสื้อผ้าและสินค้าประเภทอื่นบนแกนเดียวกัน

## ความถูกต้องและสิทธิ์

- `app.settlement_lines` เป็น append-only และใช้ FORCE RLS แยก tenant/shop
- รหัสบรรทัดต้นทางไม่ซ้ำในร้าน การส่งข้อมูลเดิมซ้ำไม่เพิ่มยอด และข้อมูลที่ใช้รหัสเดิมแต่รายละเอียดต่างกันถูกปฏิเสธ
- วันที่และยอดรวมของรหัสรอบโอนเดียวกันต้องตรงกันทุกบรรทัด
- trigger ฐานข้อมูลบังคับให้รายการแก้กลับคัดลอกมิติและจำนวนเงินจากรายการเดิมครบ และห้ามแก้กลับรายการแก้กลับ
- Owner และ Finance เพิ่มหรือแก้กลับได้ Auditor อ่านหลักฐานได้ บทบาทอื่นถูกปฏิเสธ
- summary คำนวณจากข้อมูลทั้งหมด ส่วนหน้ารายละเอียดจำกัดล่าสุด 100 รายการเพื่อไม่ให้ยอดรวมคลาดเคลื่อนเมื่อข้อมูลเพิ่มขึ้น

## UX

- ฟอร์มคงรหัสรอบโอน วันที่ และยอดรวมไว้หลังบันทึก เพื่อเพิ่มหลาย allocation ในรอบเดียวกันได้เร็ว
- แยกตาราง **รอบโอน** และ **เทียบตามคำสั่งซื้อ** เพื่อให้เห็นว่าความต่างเกิดที่ระดับใด
- รายการไม่พบออเดอร์ยังถูกเก็บเป็นหลักฐาน แต่รอบโอนยังอยู่ในสถานะต้องตรวจ
- หน้าจอมือถือใช้การ์ดสำหรับประวัติและไม่มี page overflow; ปุ่มแก้กลับอยู่กับบรรทัดต้นทาง
- หน้าจอระบุชัดว่ายอดมาจาก statement ที่ผู้ใช้ยืนยัน และยังไม่ใช่รายการเดินบัญชีธนาคาร

## ผลตรวจ

- TypeScript, ESLint, migration และ production build ผ่าน
- Integration tests **68/68** ผ่าน รวม payout หลาย allocation, ออเดอร์ข้ามหลาย payout, partial refund, unmatched order, replay/conflict, reversal, role/tenant isolation และ append-only grants
- Browser tests **19/19** ผ่าน พร้อม web และ worker จริง เส้นทางใหม่ทดสอบบน 390 px ตั้งแต่นำเข้าออเดอร์ → เพิ่ม statement allocation → เห็น payout กระทบครบและออเดอร์ตรงกัน

## ขอบเขตที่ยังไม่รับรอง

- ข้อมูล settlement ยังเป็นสัญญากลางและกรอกด้วยผู้ใช้ ยังไม่ได้รับรอง schema จริงหรือเชื่อม API ของ TikTok, Shopee และ Lazada
- ยังไม่ใช่ bank reconciliation เพราะไม่มี bank feed หรือรายการเดินบัญชีมายืนยันว่าเงินเข้าบัญชีแล้ว
- ยังไม่ได้รองรับ reserve, payout timing, withholding tax, VAT, FX และ adjustment code เฉพาะแพลตฟอร์ม ต้องยืนยันจาก statement จริงก่อนเพิ่ม semantics
- ตัวเลขทดสอบเป็น synthetic data ยังต้องทำ UAT กับผู้ดูแลร้านโดยใช้ไฟล์ที่ตัดข้อมูลส่วนบุคคลไม่จำเป็นออก
