# UX-MER-02 — เพิ่มสินค้าสำหรับผู้ใช้ครั้งแรก

วันที่: 2026-10-18
สถานะ: ส่งมอบใน local และผ่านการตรวจทางเทคนิค; ยังไม่ใช่ผล UAT กับร้านจริง

## ผลลัพธ์ที่ต้องการ

ผู้ค้ากรอกสินค้าแบบเดียวได้จากข้อมูลหลัก และเพิ่มสี ขนาด ความจุ กลิ่น หรือตัวเลือกที่ตั้งเองได้ในฟอร์มเดียว โดยไม่สูญเสียความสามารถหลายหมวดสินค้าและราคาแยกตามตัวเลือก

## ขอบเขตที่เปลี่ยน

- จัดข้อมูลเป็น 1) สินค้าอะไร 2) ราคาและรหัสสินค้า 3) มีตัวเลือกหรือไม่
- ย้ายรายละเอียดร่วม เช่น วัสดุ/ส่วนประกอบ/วิธีดูแล ไปไว้ส่วนเปิดเพิ่มท้ายฟอร์ม ไม่บังคับกรอกและไม่ล้างค่าขณะย่อส่วนนี้
- เพิ่มปุ่มช่วยตั้งรหัสสินค้าเมื่อช่องยังว่าง ใช้รหัสสุ่มที่แก้ได้และยังตรวจ uniqueness ฝั่ง server ตามเดิม ไม่อ้างว่าเป็นรหัส marketplace หรือรับประกันไม่ชนกัน
- หากร้านมีรหัสในรายงานอยู่แล้ว ให้ใช้รหัสเดิม พร้อมอธิบายว่า SKU ใช้แยกสินค้าแต่ละแบบ
- แนะนำชื่อตัวเลือกที่ใช้บ่อยแต่ยังพิมพ์ชื่ออื่นเองได้ ค่าหลายค่าป้อนทีละค่า/Enter/จุลภาคได้ตามเดิม; ขนาดยังมี S/M/L/XL ให้เพิ่ม
- เปลี่ยนปุ่มเป็น “สร้างรายการตัวเลือก” และ “อัปเดตรายการตัวเลือก” พร้อมระบุว่ายังไม่ได้บันทึกจนกดบันทึกสินค้า
- บนมือถือแสดงแถวตัวเลือกเป็นช่องกรอกแนวตั้งพร้อมชื่อช่อง ไม่สร้าง input ซ้ำสำหรับ desktop/mobile และไม่ต้องเลื่อนตารางแนวนอน
- ต้นทุนว่างยังเป็น unknown/null ไม่ใช่ศูนย์; ราคาและต้นทุนในรายการที่สร้างแล้วคงเดิมจนผู้ใช้ยืนยันใช้ค่าด้านบนกับทุกรายการ
- เปิดรายละเอียดที่ย่อไว้เมื่อ native validation พบช่องที่จำเป็นยังว่าง เพื่อให้กลับไปแก้ได้
- คง dirty form warning, confirmation, validation, variant regeneration, SKU uniqueness, tenant/shop/role scope และ API/database เดิม

ไม่เปลี่ยนฟอร์มแก้ไขสินค้าเดิม สต็อกจริง ช่องทางขาย หรือสูตรต้นทุนในรอบนี้ คำว่า “บันทึกสินค้า” ยังคงเป็นการสร้างสินค้าในร้านที่เลือก ไม่ใช่เผยแพร่ไป marketplace

## ตรวจรับทางเทคนิค

ผ่าน `npm run typecheck`, `npm run lint`, `npm run build` และ `git diff --check`

Browser tests ผ่าน 14 กรณี: foundation 10 และ product entry 4 (ตรวจ product entry ซ้ำหลังแก้การเปิดรายละเอียดและความกว้างช่องกรอกมือถือแล้ว):

- Foundation: สินค้าหลายหมวด, 6 ตัวเลือกจริง, เพิ่ม/ลบค่า, ค่าซ้ำ, คงราคาและรหัสหลังสร้างตัวเลือกใหม่, สิทธิ์และขอบเขตร้าน
- Product entry: เพิ่มสินค้าแบบเดียวโดยไม่เปิดรายละเอียด, auto code + unknown cost, validation ของรายละเอียดที่ย่อไว้, ความจุ 2 แบบบนมือถือ 320px, cancel/confirm การเปลี่ยนราคาทั้งหมด, server duplicate rejection แล้วแก้ต่อได้

ตรวจภาพจริงทั้ง desktop และ mobile 320px แล้ว เพิ่ม assertion ความกว้างช่องรหัส/ราคาเพื่อป้องกัน regression ที่ตารางไม่ล้นแต่ช่องกรอกยังเล็กเกินไป ภาพ: `artifacts/product-entry-desktop.png`, `artifacts/product-entry-options-320.png`

## UAT ที่ยังต้องทำ

ให้ผู้ค้าใหม่ลองเพิ่มสินค้าแบบเดียวและสินค้า S/M/L โดยไม่บอกตำแหน่งปุ่ม สังเกตว่าเข้าใจความต่างระหว่างรายละเอียดร่วมกับตัวเลือกหรือไม่ และทราบว่าต้องกดบันทึกหลังสร้างรายการหรือไม่ ใช้แผนทดสอบกับร้านจริงใน [UX-MER-01–05](56-merchant-first-ux.md)
