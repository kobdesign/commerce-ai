# แก้ไขสินค้าและประวัติต้นทุน — v0.3

## สิ่งที่ใช้งานได้

เปิด **สินค้า → ขยายสินค้าที่ต้องการ → แก้ไขสินค้า** ด้วย owner หรือ finance ในร้านที่เกี่ยวข้อง

- แก้ชื่อ หมวด หน่วยขาย และรายละเอียดแบบ key/value ได้ โดยไม่ผูกกับสินค้าประเภทเสื้อผ้า
- แก้ราคาขายและต้นทุนราย SKU ได้ เงินเก็บเป็นจำนวนเต็มสตางค์
- ต้นทุนว่างหมายถึงยังไม่ทราบ; 0 หมายถึงทราบว่าต้นทุนเป็นศูนย์ ทั้ง catalog และการตรวจ CSV ใช้ความหมายเดียวกัน
- การเปลี่ยนต้นทุนต้องมีเหตุผล 3–500 ตัวอักษร เพิ่มประวัติใหม่พร้อมผู้บันทึกและเวลาที่มีผล ข้อมูลเดิมไม่ถูกเขียนทับ
- การแก้เฉพาะรายละเอียด/ราคาไม่เพิ่มประวัติต้นทุนซ้ำ
- หน้าแก้ไขแสดงประวัติล่าสุดสูงสุด 100 รายการ พร้อม SKU ต้นทุน เวลาในประเทศไทย และเหตุผล
- รายการการทำงานบันทึก product.updated พร้อม version และจำนวน SKU ที่เปลี่ยนต้นทุน
- เมื่ออีกแท็บบันทึกไปก่อน API คืน 409 STALE_PRODUCT เก็บข้อความที่ยังไม่บันทึกไว้ในฟอร์ม ปิดการบันทึกซ้ำ และให้ผู้ใช้ยืนยันก่อนโหลดข้อมูลล่าสุด
- มีคำเตือนก่อนออกด้วยปุ่มกลับ/ยกเลิก และก่อนปิดหรือ reload หน้าเมื่อมีการแก้ไข

## การเก็บข้อมูลและสิทธิ์

Migration 0004 เพิ่ม version ของสินค้า และ note/created_by ของประวัติต้นทุน อนุญาต amount_minor เป็น NULL เพื่อบันทึกการกลับเป็น unknown โดยไม่ดึงต้นทุนเก่ามาใช้ผิด ข้อมูลเดิมยังอยู่; ประวัติเดิมที่ไม่มีผู้บันทึกจะคง NULL

GET/PATCH `/api/tenants/:tenantId/products/:productId` ตรวจ session, สมาชิกองค์กร, บทบาท และร้าน ฝั่ง PATCH ตรวจ Origin, ขนาด JSON, schema, version และรายการ variant IDs ครบชุด สินค้าต่างบริษัท/ต่างร้าน หรือการแทรก SKU จากสินค้าอื่นไม่ผ่าน

Product/variant UPDATE และ cost INSERT มี RLS บังคับให้เป็น owner/finance และเข้าถึง **ทุกร้านที่เชื่อมกับสินค้า** เนื่องจาก product/price/cost เป็นข้อมูลร่วมกัน ไม่เปิดให้ผู้มีสิทธิ์เพียงบางร้านเปลี่ยนข้อมูลของร้านที่ไม่มีสิทธิ์ ประวัติต้นทุนยังเป็น append-only; runtime role ไม่มี UPDATE/DELETE บน cost_versions

อ่านหน้าแก้ไขด้วย shared row lock เพื่อให้ version, รายละเอียดและต้นทุนตรงกัน บันทึกด้วย product row lock และตรวจ version จากนั้นแก้รายละเอียด ราคา เพิ่มต้นทุนและ audit ใน transaction เดียว เมื่อข้อมูลเก่าหรือ validation ไม่ผ่านไม่มีการบันทึกบางส่วน

## ขอบเขตที่ยังไม่ทำ

- ยังไม่เพิ่ม/ลบ/เปลี่ยนรหัส SKU หรือตัวเลือกของสินค้าที่บันทึกแล้ว เพื่อรักษาตัวตนที่ใช้จับคู่รายงาน การสร้างสินค้าใหม่ยังใช้ระบบตัวเลือกเดิมได้
- ต้นทุนมีผล ณ เวลาบันทึก ยังไม่รองรับย้อนหลัง/ตั้งเวลาล่วงหน้าและยังไม่ใช่ระบบตีราคาสต็อก FIFO/เฉลี่ย การ snapshot ต้นทุนกับรายการขายเพิ่มใน [v0.4](14-confirmed-orders-and-contribution.md)
- ยังไม่มีหน้าราคาขายย้อนหลัง, pagination/export ประวัติต้นทุน หรือชื่อผู้บันทึกในตารางประวัติ (เก็บ actor ID ในฐานข้อมูลแล้ว)
- การเตือนข้อมูลยังไม่บันทึกไม่ได้ครอบคลุมทุกลิงก์ภายใน sidebar/การสลับองค์กร จึงควรบันทึกหรือกดยกเลิกก่อนเปลี่ยนพื้นที่ทำงาน
- หน้าประวัตินี้รวมอยู่ในหน้าแก้ไขสำหรับ owner/finance; auditor ยังอ่านต้นทุนปัจจุบันผ่าน catalog ได้ตามสิทธิ์เดิม
- local demo เท่านั้น ยังไม่ได้เชื่อมบัญชีร้านจริงหรือเปิด AI model calls

## การตรวจรับ

- Typecheck, lint และ production build ผ่าน
- Integration 36 tests ผ่านในฐานข้อมูลชั่วคราวแยกจากข้อมูลแอป รวม 6 tests ใหม่สำหรับประวัติ, unknown/zero cost, บันทึกชนกัน, validation rollback, tenant/role isolation และสินค้าที่ใช้ร่วมกันหลายร้าน
- Browser workflows เดิม 9 tests ผ่าน; เพิ่ม 3 tests สำหรับแก้ไขบน desktop 1280px / mobile 390px และเปิดสองแท็บบันทึกชนกัน ผ่านทั้ง 3 tests หลังแก้การรอ navigation ก่อน reload ในชุดทดสอบ
- ตรวจราคา 429.99 และต้นทุน 199.99 หลัง reload, การล้างต้นทุนเป็น unknown, เหตุผลและประวัติทั้งเก่า/ใหม่ รวมถึงการโหลด version ล่าสุดหลัง conflict
- ทดสอบด้วยข้อมูลสมมติ ไม่เปลี่ยนราคาสินค้าตัวอย่างเดิมระหว่าง browser verification
