# UX-MER-04 — เงินรับ ต้นทุน และเงินเหลือที่อธิบายได้

วันที่: 2026-10-18
สถานะ: ส่งมอบหน้าเงินรับและต้นทุนใน local และผ่านการตรวจทางเทคนิค; หน้าผู้ช่วยส่งมอบต่อใน [docs/60](60-merchant-assistant-ux.md); UAT กับผู้ค้าจริงยังเป็นงานถัดไป

## ผลลัพธ์

หน้า `/performance` ตอบคำถามธุรกิจก่อนรายละเอียด: เงินรับจากยอดขายเท่าไร หักอะไรแล้ว และเหลือเท่าไรจากข้อมูลที่ร้านบันทึก โดยไม่เรียกตัวเลขนี้ว่ากำไรสุทธิหรือยอดเงินเข้าธนาคาร

- แสดงลำดับ เงินรับจากรายงาน → หลังคืนเงิน/เครดิตที่จับคู่ → หลังต้นทุนสินค้า → หลังค่าใช้จ่ายร้านที่บันทึก
- ระบุขอบเขตที่รวมและยังไม่ยืนยัน เช่น ค่าใช้จ่ายที่ยังไม่ได้กรอก ภาษี ความครบถ้วนทางบัญชี และเงินเข้าธนาคารจริง
- ถ้าต้นทุนขาด จะไม่แทนด้วยศูนย์ ไม่แสดงคำตอบเงินเหลือ และพาไปเติมต้นทุน
- เลือกงานถัดไปตามสถานะข้อมูล: นำเข้ารายงาน เติมต้นทุน ตรวจรายการปรับยอด หรือตรวจยอดเงินโอน
- เก็บคืนเงิน เครดิต ค่าใช้จ่าย และหลักฐานเดิมไว้ครบ แต่ย้ายเครื่องมือรองไว้ใต้ “งานอื่นเกี่ยวกับเงิน”
- เปิดคำสั่งซื้อล่าสุดและหลักฐานต้นทางเป็นรายละเอียดหลัก ส่วนยอดแยกตาม SKU และนิยามตัวเลขเปิดดูเพิ่มได้
- มือถือแสดงคำสั่งซื้อเป็นการ์ดจาก DOM ตารางชุดเดียว มีชื่อข้อมูลกำกับและไม่ต้องเลื่อนแนวนอน

## Business logic ที่คงเดิม

สูตรยังใช้ `financialSummary`, `applyFinancialEvents` และ `applyShopExpenses` เดิม ไม่มีการเปลี่ยนฐานข้อมูล API หรือ calculation version:

1. เงินรับหลังปรับยอด = เงินรับสุทธิจากไฟล์ − refund ที่จับคู่ + เครดิตค่าธรรมเนียมที่จับคู่
2. ส่วนต่างหลังต้นทุน = เงินรับหลังปรับยอด − ต้นทุนสินค้าตามวันที่ขาย
3. เงินเหลือจากข้อมูลที่บันทึก = ส่วนต่างหลังต้นทุน − ค่าใช้จ่ายร้านที่ยังมีผล

รายการปรับยอดที่ยังจับคู่คำสั่งซื้อไม่ได้ยังไม่รวม ค่าใช้จ่ายที่แก้กลับแล้วไม่มีผล และค่าธรรมเนียมในไฟล์ยังเป็นหลักฐานที่ไม่ถูกหักซ้ำ สิทธิ์ tenant/shop/role และลิงก์กลับร่างต้นทางคงเดิม

## การตรวจตาม React best practices

หน้าเป็น Server Component และเริ่มอ่านสรุปยอด รายการปรับยอด และค่าใช้จ่ายพร้อมกันด้วย `Promise.all` เหมือนเดิม จึงไม่เพิ่ม client bundle หรือ request waterfall ส่วนตารางถูกแยกเป็น component ระดับ module, ใช้ข้อมูลที่คำนวณแล้วโดยไม่เพิ่ม effect/state และใช้ semantic heading, ordered list, details, table และ link ตามหน้าที่
