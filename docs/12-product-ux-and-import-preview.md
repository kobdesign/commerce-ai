# Product workflow v0.2 — 2026-09-16

## สิ่งที่เปลี่ยนจาก Foundation

ย้ายจากหน้าจอแนะนำระบบเป็นพื้นที่ทำงาน: เอา hero banner, illustration, heading ภาษาอังกฤษและข้อความเชิงโฆษณาออก ใช้ตัวอักษรอ่านง่าย ตารางสินค้าเป็นกลุ่ม ปุ่มที่ตรงกับงาน และสถานะที่อธิบายข้อมูลจริง คงป้ายสภาพแวดล้อมทดสอบไว้ที่เดียว ไม่อ้างว่าเชื่อมร้านจริงแล้ว

หน้าสินค้าแยก product กับ SKU กดแถวสินค้าเพื่อดู SKU ราคา ต้นทุน และรายละเอียดร่วม ค้นหาได้ด้วยชื่อ/SKU/ค่าคุณสมบัติ และกรองสินค้าที่ต้นทุนยังไม่ครบได้ สิทธิ์ต้นทุนยังบังคับที่ server/database

## เพิ่มสินค้าที่ใช้งานได้จริง

เปิด /catalog/new:

1. ชื่อ หมวด และหน่วยขายเป็นข้อมูลร่วม
2. เพิ่ม/ลบรายละเอียดได้เองสูงสุด 12 คู่ เช่น ผ้า วัสดุ ประเทศ การดูแล
3. ขาย SKU เดียวได้โดยไม่บังคับรายละเอียดหรือตัวเลือก
4. เปิดหลายตัวเลือก กำหนดชื่อเองได้ 1–3 ประเภท เช่น สี/ไซซ์ หรือกลิ่น/ความจุ เพิ่มค่าทีละป้ายด้วย Enter หรือปุ่มเพิ่ม และลบแต่ละค่าได้
5. สร้างชุดตัวเลือก เช่น 2 สี × 3 ไซซ์ = 6 SKU สูงสุด 100 SKU ต่อสินค้า
6. ตรวจ/แก้รหัส ราคา ต้นทุน และลบชุดที่ไม่ได้ขายก่อนบันทึก ต้นทุนไม่ทราบใช้ null ไม่ใช้ศูนย์
7. บันทึกทั้ง product, variants, costs และ audit ใน transaction เดียว ไม่ทิ้งสินค้าครึ่งชุดเมื่อ SKU ซ้ำ

ตัวเลือกขนาดมีปุ่มเพิ่ม S, M, L, XL พร้อมกัน รองรับการวางหลายค่าคั่นด้วย comma/ขึ้นบรรทัดใหม่และแจ้งค่าซ้ำโดยไม่เพิ่มซ้ำ ค่าที่กำลังพิมพ์ถูกรวมเมื่อกดสร้างรายการ SKU ไม่ละทิ้งเงียบ ๆ Enter ในช่องค่าไม่ส่งฟอร์มสินค้า และไม่รบกวนการยืนยันข้อความผ่าน IME

การเปลี่ยนตัวเลือกต้องกดอัปเดตรายการก่อนบันทึก ราคา/รหัสที่แก้ในชุดเดิมจะคงอยู่ ชุดใหม่ใช้ค่าเริ่มต้นและเลือกรหัสลำดับที่ยังไม่ถูกใช้ เพื่อไม่ชนกับ SKU ที่แก้ไว้ การอัปเดตสร้างทุก combination ใหม่จึงอาจนำแถวที่ลบใน preview กลับมา มีข้อความแจ้งในหน้าจอ

ชื่อรายละเอียดและชื่อตัวเลือกต้องไม่ชนกัน ตรวจ duplicate case/whitespace/Unicode-normalized ในสัญญาข้อมูล ระบบนี้ยังไม่ใช่ unlimited schema builder: มีข้อจำกัดขนาดชัดเจน และยังไม่รองรับรูปภาพ, barcode, stock, category-specific typed fields หรือ unit conversion

การแก้ไขสินค้าที่บันทึกแล้วและประวัติต้นทุนเพิ่มใน [v0.3](13-product-editing-and-cost-history.md)

ข้อมูลที่สร้างบันทึกลง PostgreSQL จริงในสภาพแวดล้อม local ไม่ใช่ state ที่หายหลัง reload ข้อมูลเดิมจากรุ่นแรกยังอ่านได้ migration เพิ่มคอลัมน์ ไม่ลบหรือเขียนทับสินค้าเดิม

## การนำเข้าข้อมูลรอบนี้

ขั้นยืนยันนำเข้าและหน้าสรุปเงินรับ/ต้นทุนเพิ่มแล้วใน [v0.4](14-confirmed-orders-and-contribution.md) เนื้อหาด้านล่างอธิบายขอบเขต preview ของ v0.2

เปิด /imports ด้วย owner หรือ finance:

เลือก CSV → จับคู่คอลัมน์ → ตรวจรายการ → บันทึกร่าง → เปิดร่างกลับมา

- CSV UTF-8, 1 MB, สูงสุด 1,000 records และ 40 คอลัมน์ รองรับ comma/semicolon/tab และ quoted multiline ด้วย [csv-parse](https://csv.js.org/parse/api/sync/)
- สัญญาไฟล์นี้เป็น generic order-line preview ไม่ใช่ TikTok/Shopee/Lazada adapter ที่รับรองแล้ว
- ต้องมี order ID, SKU, integer quantity, วันที่ YYYY-MM-DD และยอดขายสุทธิต่อรายการใน THB ผู้ใช้ต้องยืนยันความหมายของคอลัมน์เงินเอง
- อ่านเงินเป็น integer minor units ตรวจวันที่จริง, จำนวน, SKU ที่มีสิทธิ์ในร้าน, ต้นทุนที่ขาด และรายการเหมือนกันภายในไฟล์
- ความเหมือนภายในไฟล์เป็นข้อสังเกต ไม่ตัดทิ้งเอง เพราะ order/SKU ซ้ำอาจมีความหมายทางธุรกิจ
- แถวผิดแสดงเหตุผลและลำดับ record ชัดเจน ไม่เงียบข้ามแถว; quote/column structure ที่อ่านไม่ได้ปฏิเสธทั้งไฟล์
- การเลือกคอลัมน์ล่วงหน้าใช้ชื่อ header ตรงตามกฎ ไม่ใช่ผลจาก AI
- ร่างเก็บ mapped preview, mapping, SHA-256 ของข้อความ CSV, parser version, actor และเวลา ไม่เก็บไฟล์ดิบหรือคอลัมน์ที่ไม่ได้เลือก ผู้ใช้ต้องเก็บไฟล์ต้นฉบับสำหรับตรวจย้อนกลับ
- บันทึกซ้ำด้วยไฟล์/ร้าน/mapping/version เดิมคืน draft เดิม ไม่สร้างข้อมูลซ้ำ ผล preview เป็น snapshot ณ เวลาบันทึก ไม่อัปเดตตาม catalog ภายหลัง
- ตารางร่างมี FORCE RLS, tenant/shop foreign keys และ role/actor checks ผู้ตรวจสอบอ่านได้แต่ส่งไฟล์ไม่ได้ การตลาด/ปฏิบัติการอ่านไม่ได้
- ไฟล์และผลตรวจไม่ถูกส่งให้โมเดล AI

**ยังไม่สร้าง order/financial events ไม่กระทบยอดรับเงิน และไม่คำนวณกำไร** แม้ทุกแถวผ่านรูปแบบก็ไม่ได้ยืนยันว่าความหมายยอดเงินถูกต้อง ยังไม่รองรับ returns, settlement statements, ad spend, XLSX หรือ FX ไฟล์ตัวอย่างที่ดาวน์โหลดเป็น synthetic

v0.4 เพิ่ม commit สำหรับสัญญาไฟล์กลางแบบ synthetic แล้ว ส่วน raw source storage/retention, marketplace schemas, order-line IDs, corrections และ financial semantics จากแพลตฟอร์มจริงยังต้องตรวจรับก่อน pilot

## ผลตรวจ

- Typecheck, lint และ production build ผ่าน
- Integration 30 tests ผ่าน รวม transaction ของหลาย SKU, schema validation, RLS/permission, CSV quoted lines, exact money, row errors, duplicate draft concurrency และ revoked shop access
- Browser 9 tests ผ่าน รวมสร้างสินค้ารายละเอียด 3 คู่พร้อม 6 SKU แล้ว reload, นำเข้าไฟล์ผิดบางแถว บันทึกและเปิดร่างกลับมา
- เพิ่มการตรวจป้ายขนาดบน desktop 1280px และมือถือ 390px: Enter ไม่ส่งฟอร์ม, ป้องกันค่าซ้ำ, ลบค่า, รวมค่าที่พิมพ์ค้าง, รักษาราคา/SKU เมื่อสร้างใหม่ และบันทึกแล้ว reload
- แก้ข้อความสำหรับ screen reader ในหัวตารางให้อยู่ภายในพื้นที่ตารางที่เลื่อนได้ ไม่ทำให้ทั้งหน้ามือถือล้น
- ตรวจภาพหน้ารายการ/แบบฟอร์มบน desktop และมือถือ 390px ไม่พบ page overflow หรือ framework error overlay ในหน้าที่ตรวจ
- ไม่มี live model calls, ไม่ได้ทดสอบข้อมูลส่งออกของร้านจริง หรือรับรอง production/Enterprise readiness
