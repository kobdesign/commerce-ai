# บัญชีค่าใช้จ่ายระดับร้าน — v1.0

วันที่ตรวจรับ: 17 กันยายน 2026

## ปัญหาธุรกิจ

ส่วนต่างจากยอดขายและต้นทุนสินค้ายังไม่สะท้อนค่าโฆษณา ค่าขนส่งที่ร้านออกเอง ค่าแพ็ก เงินเดือน การเดินทาง และค่าใช้จ่ายบริษัท ร้านจึงอาจเห็นส่วนต่างเป็นบวกทั้งที่เงินเหลือจริงไม่พอ ระบบรุ่นนี้เพิ่มบัญชีค่าใช้จ่ายระดับร้านโดยไม่บังคับกระจายยอดไปยังคำสั่งซื้อหรือ SKU เมื่อไม่มีหลักฐานรองรับ

## Flow ที่ใช้งานได้

เจ้าของหรือฝ่ายการเงินเปิด **ค่าใช้จ่ายร้าน** แล้วบันทึก:

- หมวดค่าใช้จ่าย: โฆษณา ขนส่ง แพ็ก เงินเดือน/แรงงาน เดินทาง/น้ำมัน หรืออื่น ๆ
- วันที่ จำนวนเงิน และเอกสารอ้างอิงที่ไม่ซ้ำในร้าน
- ค่าใช้จ่ายของร้านโดยตรง หรือยอดที่แบ่งจากค่าใช้จ่ายส่วนกลาง
- วิธีแบ่งเมื่อเป็นค่าใช้จ่ายส่วนกลาง เช่น 40% ตามสัดส่วนยอดขาย
- รายละเอียดหรือหลักฐาน และการยืนยันว่ายอดนี้จ่ายแยกจากเงินรับสุทธิ

หน้าบัญชีแสดงยอดที่ยังมีผล แยกตามหมวด ประวัติ และสถานะการแก้กลับ หน้า **เงินรับและต้นทุน** แสดง `ส่วนต่างหลังปรับยอด − ค่าใช้จ่ายร้านที่ยังมีผล` เป็น **เงินเหลือหลังค่าใช้จ่ายที่บันทึก** พร้อมคำอธิบายชัดเจนว่ายังไม่ใช่กำไรสุทธิทางบัญชีหรือยอดเงินในธนาคาร

## กติกาและความถูกต้อง

- ไม่รับหมวดค่าธรรมเนียมแพลตฟอร์มในบัญชีนี้ เพราะเงินรับสุทธิที่นำเข้าต้องรวมผลของค่าธรรมเนียมอยู่แล้ว
- ผู้ใช้ต้องยืนยันว่ายอดไม่ได้รวมในเงินรับสุทธิหรือรายการค่าใช้จ่ายอื่น เพื่อป้องกันการหักซ้ำ
- ค่าใช้จ่ายส่วนกลางรับเฉพาะยอดที่แบ่งให้ร้านแล้วและต้องมีวิธีแบ่ง ระบบไม่คิดสัดส่วนเอง
- เอกสารอ้างอิงและ advisory lock ป้องกัน replay หรือคำขอพร้อมกันเพิ่มยอดซ้ำ
- รายการเป็น append-only ไม่มีสิทธิ์ UPDATE/DELETE การแก้ไขสร้างรายการตรงข้ามและผูกกับต้นฉบับ
- ต้นฉบับหนึ่งรายการแก้กลับได้ครั้งเดียว และไม่อนุญาตการแก้กลับซ้อน
- trigger ฐานข้อมูลบังคับให้หมวด จำนวนเงิน สกุลเงิน และวิธีแบ่งของรายการแก้กลับตรงกับต้นฉบับ
- RLS จำกัดข้อมูลตาม tenant และ shop; owner/finance บันทึกได้, auditor อ่านได้, marketing เข้าถึงไม่ได้
- ทุกการบันทึกและแก้กลับสร้าง audit event `shop_expense.recorded` หรือ `shop_expense.reversed`

## ผลตรวจ

- TypeScript, ESLint, migration และ production build ผ่าน
- Integration tests **59/59** ผ่าน รวม replay, allocation evidence, role/tenant isolation, append-only grants และ forged reversal ที่ฐานข้อมูลปฏิเสธ
- Browser tests **18/18** ผ่าน รวม flow มือถือจากบันทึกค่าโฆษณาส่วนกลาง → ตรวจผลต่อเงินเหลือ → แก้กลับ → ตรวจยอดกลับเป็นศูนย์
- ตรวจ viewport 390 px แล้วไม่พบ page-level horizontal overflow ประวัติแสดงเป็นการ์ด และปุ่มแก้กลับมีพื้นที่แตะอย่างน้อย 44 px

## ขอบเขตที่ยังไม่รับรอง

- เป็นการบันทึกด้วยมือและ THB-only ยังไม่เชื่อม statement โฆษณา ใบเสร็จ payroll หรือระบบบัญชี
- เป็นยอดตลอดช่วงข้อมูลที่บันทึก ยังไม่มีตัวกรองงวดบัญชี การปิดงวด accrual ภาษีมูลค่าเพิ่ม หรือ FX
- แสดงประวัติ 100 รายการล่าสุด ยังไม่มี pagination, attachment storage, approval workflow หรือ bulk import
- ไม่จัดสรรค่าใช้จ่ายลง order/SKU และไม่เรียกผลลัพธ์ว่ากำไรสุทธิ
- ต้องยืนยันสูตรกับผู้ดูแลการเงินและทดสอบด้วยข้อมูลจริงที่ตัดข้อมูลส่วนบุคคลก่อนใช้ตัดสินใจทางบัญชี
